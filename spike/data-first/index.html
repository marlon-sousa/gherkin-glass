Data-first spike

Every page here is drawn by one script from shared data: one store of blocks, each kept once under the hash of its content, and one list per version of the blocks it holds. The HTML of each version is one small file that holds no content. Nothing here is gherkin-glass 2.0 yet; it is for trying the idea with a screen reader.

The content is the project site's example suite, as two versions: v1.0.0, as the suite is, and v1.1.0, where one step changed, one scenario was renamed, one was added and one removed.

The two forms of address

  • Addresses after a hash, such as index.html#lending/borrowing#how-long-a-loan-lasts. Moving between pages stays in one document, so the script announces each new page and moves the focus.
  • Addresses in a query, such as index.html?page=lending/borrowing#how-long-a-loan-lasts. Moving between pages loads the page again, as today.

What to try

  • A link straight to a scenario, such as a scenario outline, hash form and the same, query form: the page should open with the focus on that scenario's heading.
  • A row of an outline, inside collapsed blocks: hash form and query form.
  • Moving from a folder page to a feature, and back with the browser's back button.
  • The contents of a feature page, the skip link, and the headings.
  • "This page in other versions" at the top of a feature page, and "In other versions" in each scenario, both from the hashes: compare lending/borrowing in v1.1.0 and catalogue/searching in v1.1.0.

Not in the spike: the folder tree, search, tag pages, step sentences, the backgrounds shown inside each scenario, and remembering what was collapsed.
